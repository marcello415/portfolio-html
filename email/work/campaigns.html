Promotional & Lifecycle Email

Building and deploying 10,000+ promotional and lifecycle emails for Gap Inc. brands in Salesforce Marketing Cloud.

The job

Gap, Gap Factory, Gap Factory Canada and Old Navy sent promotions and lifecycle emails every week. A data team built the segments and a deployment team handled sends. I built and checked the emails in between: HTML, AMPscript and the test data behind them.

What I did

  1. Built promotional emails for free shipping, GapCash, Black Friday and Cyber Monday
  2. Built lifecycle emails, including welcome, birthday and tier upgrade
  3. Coded in HTML, CSS and AMPscript in Salesforce Marketing Cloud
  4. Built test data extensions with custom fields for QA
  5. Checked tracking links on every test send
  6. Managed handoffs with producers in Asana

GapCash, up close

GapCash was Gap’s rewards offer. Customers earned it during one window and spent it during the next. That meant every GapCash promotion was really two emails in one send, and the details had to match the offer sheet exactly.

Earner versionPeople who earned GapCash

Their balance, the redeem tiers (for example, $20 off $50, $40 off $100, $120 off $300) and an in-store barcode.

Non-earner versionEveryone else

The same promotion and products, with no redeem block, so nobody saw an offer they couldn’t use.

To show how it worked, I rebuilt a GapCash redeem email from the original Gap Factory images and footer. The balance, the redeem rows and the barcodes all come from the customer’s record, so one email covers both versions. The working versions under See the work use test data.

How I built it

  1. Put the customer’s balance in the subject line with AMPscript, with a fallback when the first name was missing
  2. Wrote the same logic in French for Gap Factory Canada, where GapCash is DollarsGap
  3. Used toggles at the top of each email to show or hide the rewards, free shipping and promo banners per send
  4. Pulled shared content blocks for legal copy, rewards and send-date logic, so one fix updated every email
  5. Gave each customer a unique promo code with ClaimRow when an offer needed one
  6. Added Movable Ink blocks for live content like countdown timers

A line from the code

%%[ set @subjectLine = Concat(
  iif(Empty(@first_name), "It's",
    Concat(ProperCase(Trim(@first_name)), ", it's")),
  " time to use your $", @GC_TOTAL, " in GapCash!") ]%%

“Marcello, it’s time to use your $40 in GapCash!” If the name field is empty, it reads “It’s time to use your $40 in GapCash!”

The redeem rows

%%[ set @codeRows = LookupOrderedRows("GapCash_Codes", 0,
  "SpendMin DESC", "EmailAddress", @email)
for @i = 1 to RowCount(@codeRows) do
  set @row = Row(@codeRows, @i) ]%%
  Redeem $%%=Field(@row, "RedeemValue")=%% in GapCash
  when you spend $%%=Field(@row, "SpendMin")=%%.
  <img src="%%=BarcodeURL(Field(@row, "Code"), "Code128", 275, 64)=%%">
%%[ next @i ]%%

One row per redeem tier, highest spend first, each with its own barcode. A customer with no codes gets the non-earner version.

How I checked it

  1. Built test records for each case: earner, non-earner, no first name and each balance tier
  2. Checked every amount, date and exclusion against the final offer sheet
  3. Confirmed the barcode and promo code showed only in the earner version
  4. Previewed the English and French versions side by side for Canada
  5. Ran Litmus across Outlook, Gmail, Apple Mail and mobile before handoff

Where it carries over

Loyalty email works the same way in any industry. Points, tiers and redeem windows replace GapCash, and the core job doesn’t change: show each member the offer they actually qualify for, with the right balance, dates and code.

How it helped

Our team of 15 coded 10,247 emails over four years. Building GapCash as one email with two versions, with a test record for every case, gave each offer a clear checklist before handoff.
