Product Detail Pages

Setting up product detail pages for the Apple Online Store and Apple Store app across 88 countries, from developer handoff to staging check.

Apple (Contract)
Role
Content Specialist

The job

Every product needed a detail page that looked right in each market, in the online store and the app. Developers handed off code and stylesheets. My job was to get that content into the CMS and live without errors.

What I did

  1. Set up product detail pages in a proprietary CMS for 88 countries
  2. Published up to 1,000 product parts a month, including data entry, metadata and release
  3. Entered developer code handoffs into the CMS and loaded updated stylesheets
  4. Set up page content by market and customer segment, with separate versions where markets shared a language
  5. Checked every page in staging before launch
  6. Tracked requests in Jira-style tickets and raised blockers in daily stand-ups

Product pages, up close

A product detail page is mostly data. Each part has a product code, name, color or size, and copy for every market. The page template pulls it all together, so if one field is wrong, the page is wrong.

By marketDifferent pages for different stores

Each country got its own version, with content set up by market and customer segment.

Shared languagesSame language, separate versions

Markets that share a language still got their own version, so each market kept its own details.

How I built it

  1. Entered product data and metadata from each request, part by part
  2. Loaded developer code handoffs and updated stylesheets into the CMS
  3. Set up content by country and customer segment
  4. Coordinated translations for 88 countries and matched them to the right pages
  5. Released pages on the scheduled date, up to 1,000 parts a month

How I checked it

  1. Previewed every page in staging before launch
  2. Compared names, colors and codes on the page against the request
  3. Checked shared-language markets side by side so each showed its own version
  4. Raised blockers in daily stand-ups when a request was missing information

How it helped

Checking every page in staging caught problems before customers saw them, and separate versions for shared-language markets kept each storefront showing the right content.
