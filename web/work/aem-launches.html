AEM Launch Pages

Setting up Apple.com launch pages in Adobe Experience Manager for 100+ locales, and running the weekly navigation release.

Company
Apple (Contract)
Role
Content Manager
Years
2024–25
  • 100+locales per launch
  • Weeklynavigation release
  • ~30%faster QA with a tool I built

The job

Apple.com launches run on tight, shifting schedules, often several at once. Each launch page had to be built in AEM with the right structure, assets and localized copy for every locale.

What I did

  1. Set up page structure, assets and localized copy in AEM for launches in 100+ locales
  2. Worked with developers to plan page structures and improve content fragment models, components and authoring workflows
  3. Led the weekly Apple.com navigation release and represented the team in weekly partner meetings
  4. Ran UAT in AEM author and stage and wrote up CMS bugs for developers
  5. Built a Quip tool that made QA about 30% faster, and wrote SOPs for onboarding
  6. Trained new team members in California and India

AEM, up close

A launch page in AEM is built from parts: a page template, components dropped into it, content fragments that hold reusable copy, and assets from the asset library. My job was to put those parts together for every locale and make sure each one showed the right copy and images.

Content fragmentsCopy that lives in one place

Reusable copy was set up once as a fragment, so a change carried to every page that used it.

ComponentsThe building blocks of a page

Page sections were placed and configured per page, then filled with localized copy and assets.

See it working

Apple’s setup stays private, so I built a working demo with a made-up brand. It shows a launch page made from content fragments and assets in five locales, a launch that stages the next release, and the UAT checks I ran before it went live.

/content/dam/northwind/fragments/fr-FR/arc-pro/hero
{
  "title": "Arc Pro 2",
  "subtitle": "Deux fois plus de silence. Le même confort.",
  "primaryLabel": "En savoir plus",
  "primaryLink": "/fr/arc-pro/",
  "asset": "/content/dam/northwind/arc-pro/arc-pro-2_hero_midnight.png"
}

One fragment per locale. The copy changes by language, and every link has to start with that locale’s path. A French page linking to a /us/ page is the kind of miss UAT catches.

How I built it

  1. Set up the page structure from the launch plan: which components, in which order, for which locales
  2. Placed assets from the asset library and checked each locale pointed to its own images
  3. Entered localized copy for 100+ locales and matched each one to its translation
  4. Worked with developers when a fragment model or component didn’t fit the content, and suggested changes
  5. Wrote SOPs for the steps new team members found hardest

How I checked it

  1. Ran UAT in AEM author, then again in stage, before anything went live
  2. Checked copy, images, links and footnotes in each locale against the launch plan
  3. Wrote up bugs so developers could reproduce them: page, locale, steps and what I expected
  4. Re-checked fixes in stage before signing off

What I bring to an AEM role

Day to day I work in pages, components, content fragments and assets, and I know the author-to-stage-to-live flow. I can take a launch plan, build it out across locales and catch problems before they reach customers.

How it helped

Better fragment models and written SOPs made authoring more consistent, and the QA tool gave the team time back on every release.
